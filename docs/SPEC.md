# hikidashi 공통 명세

웹앱(`/`, React)과 iOS 앱(`ios/`, SwiftUI)이 같이 지켜야 하는 약속. 한쪽에서 기능이나 데이터를 바꾸면 이 문서를 먼저 고치고, 아래 **기능 맞춤표**에 두 앱의 상태를 적는다.

## 데이터

두 앱은 서로 다른 곳에 저장한다 (웹: IndexedDB, iOS: 앱 폴더의 JSON 파일). 대신 **백업 파일 형식이 같아서** 한쪽에서 내보낸 파일을 다른 쪽에서 그대로 가져올 수 있다. 나중에 서버를 붙일 때도 이 형식을 쓴다.

### 공통 규칙

- 모든 레코드는 `id`(UUID 문자열), `createdAt`, `updatedAt`, `deletedAt`(삭제 표시, 없으면 `null`)를 가진다.
- 시각은 **밀리초 단위 유닉스 시간 숫자** (JS `Date.now()`).
- 삭제는 지우지 않고 `deletedAt` 을 채운다. 되돌리면 다시 `null`.
- 합칠 때(백업 가져오기, 동기화)는 같은 `id` 면 **`updatedAt` 이 더 큰 쪽이 이긴다**.

### Folder (서랍)

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `name` | 문자열 | 서랍 이름 |
| `color` | 색 키 | 아래 색 표의 키 |
| `order` | 숫자 | 정렬 순서 (작을수록 위). 하위 서랍은 같은 상위 서랍 안에서의 순서 |
| `parentId` | 문자열 또는 `null`, 선택 | 하위 서랍이면 상위 서랍 id. **한 단계만** (하위 서랍 아래에 또 두지 않는다) |

### Item (항목)

| 필드 | 형식 | 설명 |
| --- | --- | --- |
| `kind` | `"link"` 또는 `"memo"` | |
| `url` | 문자열, 링크만 | 정규화된 http(s) 주소 |
| `title` | 문자열 | 비어 있을 수 있음. 비면 목록에서 `note` 첫 줄을 제목 자리에 쓴다 |
| `note` | 문자열 | 링크는 내용(페이지 소개문), 메모는 본문 |
| `image` | 문자열, 선택 | 글 대표 이미지 주소 |
| `video` | 문자열, 선택 | 딸린 영상 주소 (X 영상·움짤의 mp4, 영상 파일 링크). 카드에서 2초만 소리 없이 반복 재생 |
| `siteName` | 문자열, 선택 | 출처 칩에 쓰는 사이트 이름 (예: `MDN Web Docs`, `X · @hong`) |
| `emoji` | 문자열, 선택 | 직접 고른 아이콘. 있으면 이미지·로고보다 먼저 |
| `folderId` | 문자열 또는 `null` | `null` 이면 미분류 |
| `tags` | 문자열 배열 | `#` 없이 저장 |
| `starred` | 참/거짓 | 즐겨찾기 |
| `highlights` | 문자열 배열, 선택 | 리더에서 형광펜 친 문단 글 그대로. 비면 빼고 저장 |
| `brokenAt` | 숫자(ms) 또는 없음 | 링크가 열리지 않는 걸 처음 안 때 (404·410·도메인 없음만). 다시 열리면 없음 |
| `checkedAt` | 숫자(ms), 선택 | 링크 점검을 마지막으로 한 때. 깨짐 여부가 바뀔 때만 `updatedAt` 을 올린다 |
| `avatar` | 문자열, 선택 | 글 쓴 사람 프로필 사진 (X 등 SNS). 타임라인 보기의 동그란 사진 |
| `images` | 문자열 배열, 선택 | 게시물 사진 전부 (2장 이상일 때만, 최대 4장). 비면 빼고 저장 |
| `doneAt` | 숫자(ms) 또는 `null`, 선택 | 확인 완료한 때. 있으면 목록·개수에서 빠지고 "완료함" 에만 보인다 |

### 백업 파일

```json
{"app": "hikidashi", "version": 1, "exportedAt": 1762500000000, "folders": [...], "items": [...]}
```

- 파일 이름: `hikidashi-backup-YYYYMMDD-HHmm.json`
- 읽을 때 형식이 틀린 레코드는 버리고 나머지만 가져온다.
- 모르는 필드는 무시한다 (새 버전 파일을 옛 앱이 읽어도 깨지지 않게).

## 동작 규칙

- **목록 묶음**: 오늘 / 어제 / 이번 주(7일 안) / 이번 달(31일 안) / 이전. 자정 기준.
- **목록 시각**: 오늘은 시각(오후 2:07), 어제, 이번 주는 요일, 올해는 월일, 그 전은 연월일.
- **화면 구성**: 아래에 하단바(타임라인 · 미디어 · 설정)와 + 버튼이 떨어져 있다 (둘 다 리퀴드 글래스). 아래로 스크롤하면 하단바가 + 버튼 쪽으로 빨려 들어가 + 만 남고, 위로 올리거나 맨 위면 다시 나온다. 보기 전환 버튼은 위에 두지 않고, 설정은 하단바에서 연다.
- **타임라인 보기** (= 목록 보기): X 타임라인처럼. 동그란 사진(고른 이모지·메모 아이콘 → SNS 프로필 `avatar` → 사이트 파비콘), 이름 자리에 제목(X 게시물은 `@아이디`), 옆에 사이트·시간, 아래 내용 그대로(10줄까지), 그 아래 미디어(사진 여러 장은 X 처럼 2·3·4장 격자, 영상은 2초 반복, 아니면 대표 그림 한 장), 서랍·출처·태그 칩. 날짜별·사이트별 묶음은 그대로.
- **미디어 보기** (= 카드 보기): 두 줄 벽돌 카드.
- **메모 모아보기**: 서랍 목록 위쪽 "메모" 에 메모만.
- **+ 버튼 손맛**: 닿는 순간 톡 하고 버튼이 젤리처럼 옆으로 퍼지며 10% 커진다. 떼면 위이잉(세졌다 잦아드는 진동)과 함께 출렁이며 돌아온다. 웹은 안드로이드 진동, iOS 사파리는 스위치 진동을 빌려 톡 한 번.
- **하위 서랍**: 색을 따로 정하지 않고 상위 서랍 색을 따른다 (`color` 에는 만들 때 상위 색을 넣어 둔다). 칩·고르기 목록에는 `상위-하위` 로 적는다. 서랍 목록에서는 상위 바로 아래에 들여 써서 보인다. 상위 서랍을 보면 하위 서랍 항목도 같이 보이고(칩 표시), 개수도 더한다. 상위 서랍을 지우면 하위 서랍도 같이 지우고 안의 항목은 미분류로 (되돌리기 가능). 상위 서랍이 없어진 하위 서랍은 위 단계로 본다.
- **확인 완료**: 항목 메뉴(길게 누르기)의 "확인 완료" 로만 한다 (목록에 체크 칸은 없다). 완료하면 목록에서 빠지고 서랍의 "완료함" 으로. 완료함에서 "완료 취소". 여러 개 고르기에서도 된다.
- **NSFW**: `nsfw` 태그로 단다 (대소문자 상관없이, 항목 메뉴의 "NSFW 로 표시"). 서랍 머리의 설정 옆 눈 버튼으로 보이기/숨기기, 기본은 숨김(기기마다). 숨기면 목록·검색·개수·태그 목록 어디에도 안 나온다.
- **검색**: 제목·내용·주소·사이트·태그·형광펜에 더해 기기에 저장한 리더 본문까지 찾는다.
- **목록 묶음**: 날짜별(기본) 또는 사이트별(출처 칩 이름 기준, X 는 하나로, 많은 사이트부터, 메모는 맨 뒤). 목록 보기에만, 기기마다.
- **영상 카드**: `video` 가 있으면 카드 그림 자리에서 소리 없이 2초만 반복한다. 6초가 넘는 영상은 20% 지점(최대 10초)부터. 화면에 보일 때만 받고, 움직임 줄이기(웹은 데이터 절약, iOS 는 저전력 모드 포함)면 그림만. 목록 보기는 그림만.
- **파일 주소**: 주소가 영상(`mp4·m4v·webm·mov`)이나 그림(`gif·png·jpg·jpeg·webp·avif`) 파일이면 페이지를 읽지 않고 그 파일을 영상·그림으로 쓴다. 제목은 파일 이름.
- **아이콘 순서**: 고른 이모지 → 글 대표 이미지 → 사이트 로고(Google 파비콘 `s2/favicons?domain=…&sz=…`) → 서랍 색 블록 + 글자/메모 아이콘.
- **출처 칩**: 태그 맨 앞, 로고 + `siteName`(없으면 도메인).
- **링크 정보 가져오기**: 제목(사이트 꼬리 `- YouTube`, `| MDN` 떼기), 소개문(없으면 본문 첫 문단, 160자), 대표 이미지.
  - 유튜브: 영상 썸네일 `i.ytimg.com/vi/{id}/hqdefault.jpg`
  - X(트위터): FxTwitter API. 제목은 비우고 글 전체를 `note` 로, 이미지는 사진 → 영상 썸네일 → 작성자 프로필. `siteName` 은 `X · @아이디`.
  - 웹은 CORS 때문에 Jina Reader 를 거치고, iOS 는 페이지를 직접 읽는다.
  - 사용자가 고친 칸은 덮어쓰지 않는다. 정보를 받는 중에 저장하면 다 받은 뒤 저장한다.
- **태그 입력**: 스페이스·쉼표·엔터로 칩이 된다. 없는 태그는 새로 만든다. 기존 태그는 자주 쓴 순으로 추천.
- **삭제**: 확인창 없이 지우고 "되돌리기"를 보여 준다. 서랍을 지우면 안의 항목은 미분류로.
- **빠른 추가**: + 버튼을 위로 끌어올렸다 놓으면 클립보드 링크를 바로 추가하고 정보는 뒤이어 채운다. 이미 있는 주소면 알려 준다.

## 동기화 (드롭박스, 종단간 암호화)

- 드롭박스 **App folder** 권한 앱. 파일 하나 `/hikidashi-sync.enc` (앱 폴더 기준).
- 파일은 봉투 JSON 이다. 안의 내용(백업 파일과 같은 형식, 지운 표시 포함)은 기기에서 잠근다.

  ```json
  {"app": "hikidashi-sync", "v": 1,
   "kdf": {"name": "PBKDF2", "hash": "SHA-256", "iter": 600000, "salt": "<base64 16바이트>"},
   "iv": "<base64 12바이트>", "data": "<base64 암호문 ‖ 16바이트 태그>"}
  ```

  - 키: PBKDF2-HMAC-SHA256(동기화 암호를 **NFC 로 맞춘** UTF-8, salt, iter) → 32바이트. 암호화: AES-256-GCM.
  - salt 는 처음 암호를 정한 기기가 만든다. 다른 기기는 파일의 salt 로 키를 만든다. salt 가 바뀌었으면(다른 기기에서 암호를 새로 정함) 암호를 다시 묻는다.
  - 키와 드롭박스 갱신 토큰은 기기에만 둔다 (웹: IndexedDB 의 꺼낼 수 없는 CryptoKey, iOS: 키체인 이 기기 전용). 암호 자체는 저장하지 않는다.
- 한 번 맞추기: 지난번 판(rev)과 같고 이 기기에서 고친 게 없으면 끝 → 아니면 받기 → 풀기 → `updatedAt` 이 큰 쪽으로 합치기 → 이 기기에만 있거나 더 나중에 고친 게 있으면 잠가서 올리기. 올릴 때 받은 판을 붙여(`update` 모드) 그사이 다른 기기가 올렸으면 거절되고, 다시 받아 합친 뒤 올린다 (최대 3번). 파일이 없으면 새로 만든다(`add`).
- 언제: 앱을 열 때·앱으로 돌아올 때, 고친 뒤 3초, "지금 동기화", 열려 있는 동안 드롭박스 변경 알림(longpoll), iOS 는 백그라운드 새로 고침.
- 리더 본문, 썸네일, 최근 연 항목, 화면 설정은 기기마다 따로 둔다 (동기화하지 않음).

## 주소 정리

저장할 때 주소에서 추적용 꼬리를 뗀다: `utm_*`, `fbclid`, `gclid`, `igshid`, `mc_cid` 등 어디서나 떼는 것, 그리고 사이트별로만 떼는 것 (유튜브 `si`·`feature`, X `s`·`t`, 스포티파이 `si` 등), 글자 위치 조각 `#:~:text=`. 두 앱의 목록은 같다.
